## APIによる取得と更新

`npm run fetch:mufg` は保存済みの `public/live/manifest.json` と2商品の履歴を読み込み、通常基準価額の系列であることを確認してからAPIへアクセスします。使用するエンドポイントは次の2種類です。

- 最新値：`https://developer.am.mufg.jp/fund_information_latest/association_fund_cd/<投信協会コード>`
- 指定日：`https://developer.am.mufg.jp/fund_information_date/association_fund_cd/<投信協会コード>/base_date/<YYYYMMDD>`

商品名・ファンドコード・協会コード・ISINを照合し、保存する観測値は **`base_date` を変換した日付と、通常の基準価額 `nav` のみ**です。APIが返す騰落率・純資産・リスク等は保存しません。

通常の更新では、保存済み最終日の翌日からAPIの最新基準日まで、日付を1日ずつ進めて不足分を取得します。最新日の値は最新値APIの応答を再利用します。既存の過去日は再取得しません。最新日が同じ場合は2商品の最新値APIだけを確認し、値も同じなら版・作成日時を保持します。同じ最新日の基準価額が訂正されていた場合は、その最終値を固定URLのJSONへ反映し、商品の更新識別子を変更します。

日付指定APIで、HTTP 200・API成功・エラーなし・取得件数0・空のデータ配列が揃った場合のみ「その日の観測値なし」と扱います。休日を前営業日の値で補間しません。HTTP 404/500、API内のエラー、指定日と異なる基準日、応答形式の変更などは休日扱いにせず停止します。想定した空応答以外の扱いは、実際の応答仕様を確認してから変更してください。

通信はHTTPS・リダイレクト拒否・20秒タイムアウト・応答上限2MiBです。リクエストは直列で、2回目以降は1秒待ってから送信します。2商品分の全取得・検証が成功するまで配信ファイルを書き換えません。日次ジョブでは失敗時に60秒間隔で最大3回試します。

## 既存履歴の移行と初回取得

2026-09-07の変更作業では、利用者の指示に従い過去データをAPIで再取得していません。既存版 `mufg-20260904-6c4cf880560d` のオルカン1,913観測・S&P500 1,995観測は、同じセッションで取得済みだった公式データとの照合により、すべて通常基準価額と同値であることを確認済みです。

`npm run migrate:nav` は通信せず、この確認済みの版・商品別の履歴ハッシュが一致する場合だけ、日付と値を一切変更せず `valueBasis: "nav"` の新版を生成します。未確認の再投資系列を通常基準価額として読み替えることはできません。当時の移行後の版は `mufg-20260904-c18ad9a40cee` です。

保存済みの履歴がない場合、通常の取得コマンドは通信前に停止します。将来、初回から構築する必要がある場合だけ `npm run fetch:mufg -- --backfill` を明示すると、設定日から日付を順に指定してAPIで全履歴を取得します。このコマンドは今回実行していません。既存履歴がある場合は `--backfill` を指定しても差分取得となり、既存日を再取得しません。全履歴の構築には多数のリクエストと時間が必要なため、日次ジョブとは別に実行します。

## 系列の意味

`nav` は通常の基準価額（1万口あたり・信託報酬控除後）です。アプリはこの値の比率で保有分の評価額を計算します。分配金の受取額・再投資は含めず、分配金が支払われた場合の表示損益は受取分を含む投資全体の損益とは異なります。CSVだけにある再投資基準価額や税引前分配金を取得・保存・計算しません。信託報酬を再控除しません。

日付は `YYYY-MM-DD`、値は10進数文字列です。丸め直し、欠測日の補間、株価指数や他商品の接ぎ足しはしません。アプリは2商品の共通観測日だけで計算します。計算方法は [データ形式](data-format.md) を参照してください。

## 配信とアプリ

2026-09-07に、既存の価格と日付をそのまま使って固定URL形式2へ移行しました。`npm run migrate:fixed` はAPI通信なしの移行で、移行済みの場合は何も変更しません。今回の固定URL対応は未デプロイです。新アプリは旧形式も読めますが、旧アプリは形式2を読めないため、新アプリの反映後に配信を切り替えます。

生成先は `public/live/` のみで、iOSアプリには価格データを同梱しません。実データは商品ごとの固定URL `funds/<id>.json` へ上書きします。内容が変わると該当商品の更新識別子と一覧全体の識別子が変わり、同じ内容なら識別子と作成日時を保持します。今後は日々の更新で版付き履歴ファイルを追加しません。履歴ファイルを先に書き、manifestを最後に切り替えます。`npm run validate` でスキーマ・値・日付・商品・共通期間を確認してから公開します。

通常起動は実データモードです。新規インストール直後は価格データがなく、初回にCloudflareから2商品を取得・検証・保存してから表示します。初回取得に失敗した場合は結果を表示せず、再試行を案内します。取得済みならオフラインでも保存データを利用でき、更新失敗時も保持します。画面と説明に出典を記載し、商品ページへのリンクを設けています。

移行後も2026-09-04までのオルカン1,913観測、S&P500 1,995観測を保持しています。最終日の通常基準価額はそれぞれ37,945円、44,392円です。公開済みの旧版履歴はURLの互換性のため保持します。アプリは、通常基準価額と同値であることを確認した旧版だけ、版と履歴ハッシュを照合して読み込めます。

2026-09-06にCloudflareへ公開し、[実データの一覧](https://tarareba-data.hibiki-apps.workers.dev/live/manifest.json) と2商品の履歴がローカルJSONと完全に一致することを確認しました。毎朝7:17（日本時間）に取得・公開するワークフローを用意しています。有効化に必要なGitHubへの反映と認証設定は [日次更新](data-updates.md) を参照してください。

2026-09-07のAPI・通常基準価額への変更と移行版JSONの作成時には、API取得コマンド・Cloudflareへのデプロイは実行していません。その後、同日に利用者がデプロイし、`publish:verify` で公開manifest・2履歴が移行版 `mufg-20260904-c18ad9a40cee` と一致することを確認しました。

アプリは旧形式の実データが保存されている場合、前回の確認から6時間以内でも起動・復帰時に新版を確認します。更新失敗時は確認済みの保存データを保持し、次の起動・復帰や手動更新で再試行できます。通常基準価額の新版を保存した後は通常の6時間間隔に戻ります。
