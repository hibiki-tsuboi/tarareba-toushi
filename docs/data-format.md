# データ形式と計算

## 配置

実データのmanifestは `schemaVersion: 2`、`datasetVersion`、`isSample`、UTCのISO 8601 `publishedAt` と商品の `funds` を持ちます。実データの一覧は最大1,000商品まで、IDは一意です。サンプルと移行前の実データは形式1・2商品です。`currency` はJPY固定です。

| モード | manifest | 商品ID | 出典のkind |
|---|---|---|---|
| 通常の実データ | `live/manifest.json` | `all-country` / `sp500` | `official` |
| 開発用サンプル | `sample/manifest.json` | `demo-all-country` / `demo-sp500` | `synthetic` |

実データは `isSample: false` とHTTPSの出典URLが必要です。サンプルは `isSample: true` で、商品名に「サンプル」を含めます。設定モードに合わないID・出典・フラグは拒否し、キャッシュをモード別に分離します。どちらのモードも価格データを同梱せず、初回に公開URLから取得します。

`publishedAt` は配信データを作成した日時です。端末での取得日時や観測日の最終日とは異なります。実データの版が同じ場合は、確認し直しても作成日時を変更しません。

形式2の `path` は `funds/<id>.json` の固定パスです。`funds[].contentVersion` は `fund-` と商品内容のSHA-256（小文字16進数64桁）からなり、対応する履歴の `datasetVersion` と一致します。一覧全体の `datasetVersion` は英小文字・数字・ハイフンの1〜64文字、先頭は英小文字または数字です。これらは変更を判別する情報で、ファイル名には使いません。形式1では従来の `funds/<id>.<datasetVersion>.json` を使い、一覧と履歴の版が一致します。

商品IDも英小文字・数字・ハイフンの1〜64文字で、先頭は英小文字または数字です。絶対URL、親ディレクトリ、パーセントエンコード、クエリ、別ドメインの指定は許可しません。HTTPリダイレクトはすべて拒否します。

形式2では商品の内容を変えたときだけ、その商品の識別子が変わります。日付が増えない最新価格の訂正も検知できます。配信側は全商品の履歴を検証します。アプリは現在使う2商品だけを取得・検証し、一覧に追加商品があっても全履歴をダウンロードしません。追加商品の選択UI・取得対象設定は商品追加時に拡張します。

固定URLの一覧・履歴は毎回再検証するキャッシュ設定です。アプリは一覧と履歴の更新情報が違う場合、一覧から1回だけ再取得し、再び一致しなければ以前の正常なスナップショットを保持します。

各系列は一覧と同じスキーマ・モード、対応する商品ID・通貨・更新識別子と、`valueBasis`、`source`、`observations` を持ちます。未知の追加キーは無視できますが、未知のスキーマや系列基準は拒否します。

以下は形式1の開発用サンプルの系列です。

```json
{
  "schemaVersion": 1,
  "datasetVersion": "sample-v1",
  "isSample": true,
  "fundId": "demo-all-country",
  "currency": "JPY",
  "valueBasis": "reinvestedIndex",
  "source": {
    "kind": "synthetic",
    "name": "開発用に生成した架空の比較データ",
    "url": null,
    "note": "実際の運用実績ではありません"
  },
  "observations": [{"date": "2025-01-06", "value": "10000.000000"}]
}
```

## 日付と値

- 日付は1900〜2200年の実在する `YYYY-MM-DD`。昇順・重複なし。先頭と末尾がmanifestの `firstDate` / `lastDate` と一致する必要があります。
- 観測値は正の10進数文字列。整数部12桁以内、小数部6桁以内。指数表記、NaN、負数、0は禁止です。最大30,000観測/商品、HTTP応答は2MiB/ファイルまでです。
- `nav` は通常の基準価額（1万口あたり・信託報酬控除後）です。実データの新規生成はこの系列だけを使います。観測値は日付と基準価額だけを持ち、分配金の受取額・再投資は含めません。分配金が出た場合の表示損益は、受取分を含む投資全体の損益とは異なります。
- `reinvestedIndex` は開発用の架空サンプルと、端末に残る旧版キャッシュの系列名です。配信中の旧版ファイルは削除済みです。検証には引き続き対応しますが、iOSで実データとして計算に使えるのは `mufg-20260904-6c4cf880560d` のうち通常基準価額との一致を確認した履歴ハッシュだけです。未確認の再投資系列は拒否します。
- `navWithoutDistributions` は分配金なしと確認した通常基準価額用の旧形式です。互換性のため読み込めますが、新規生成には使いません。新しい `nav` は分配金の有無を前提にせず、受取額を計算対象外とします。

## 共通期間と計算

開始日は指定日以降の最初の共通観測日、終了日は最後の共通観測日です。共通観測日は**選択した商品だけ**の積集合で求めます（未選択の商品は比較期間に影響しません）。指定日がいずれかの履歴開始前、または共通終了後なら計算しません。共通日がない場合も拒否します。開始＝終了は元本と同額、損益0です。同時に比較できるのは5商品までで、3商品以上では差額の代わりに順位と最大差を表示します。

```text
評価額(t) = 元本 × 系列値(t) ÷ 系列値(開始日)
損益(t) = 評価額(t) − 元本
損益率(t) = (系列値(t) ÷ 系列値(開始日) − 1) × 100
```

内部はDecimal。表示評価額を1円単位で四捨五入し、表示損益＝表示評価額−元本、表示差額＝Bの表示評価額−Aの表示評価額とします。表示上の同額は勝者なし。率は小数1桁。税金・購入換金手数料、分配金の受取額・再投資は除外し、整数口数への丸めはしません。

## サンプルの再現性

生成はネットワーク不要で、開始・終了・seed・versionが同じなら同一です。平日の架空時系列であり、日本の祝日カレンダーや実績を再現しません。生成先は `public/sample/` のみです。固定フィクスチャはSwiftのテストターゲットに置き、UIテストではランナーから応答を渡します。`npm run validate` は配信JSONの契約に加えて、アプリのソース配下に価格データファイルがないことも確認します。
